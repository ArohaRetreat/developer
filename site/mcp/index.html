MCP server · npm

An assistant with scoped access.

Read and manage Aroha through typed tools using the same permissions and business rules as the website and Studio.

View npm package ↗Source on GitHub

Install through your MCP host

Requires Node 22 or later. Create a scoped token, store it in a private file with chmod 600, then add this configuration to your MCP host. Your host's configuration location varies.

MCP host configuration
{
  "mcpServers": {
    "aroha": {
      "command": "npx",
      "args": [
        "--yes",
        "@theharithsa/aroha-mcp@0.2.0"
      ],
      "env": {
        "AROHA_API_URL": "https://aroha-retreat-preprod.web.app/api/external/v1",
        "AROHA_API_TOKEN_FILE": "/absolute/private/path/aroha-token"
      }
    }
  }
}

Codex configuration

Codex uses TOML for stdio servers. Add the following to your private MCP configuration, or use its MCP settings UI. The token itself stays in the private file.

Codex · config.toml
[mcp_servers.aroha]
command = "npx"
args = ["--yes", "@theharithsa/aroha-mcp@0.2.0"]

[mcp_servers.aroha.env]
AROHA_API_URL = "https://aroha-retreat-preprod.web.app/api/external/v1"
AROHA_API_TOKEN_FILE = "/absolute/private/path/aroha-token"

Configuration format: official OpenAI MCP documentation. The JSON example above is for hosts using an mcpServers-style configuration.

Scoped CRUD tools

Version 0.2.0 maps the canonical API’s 106 operations to fixed, typed tools. Discovery is filtered by your token and refreshed against current capabilities. Existing mcp-readonly tokens keep the original nine-operation ceiling above. Create a new mcp token with explicit write scopes for CRUD. Include runtime:read so the server can discover capabilities.

AreaOperations and boundaries
ReservationsQuotes, requests, eligible contact updates, cancellation, changes, event offers, approvals, check-in and checkout.
FinancialsRead balances; record verified manual payments; reverse recorded payments; retrieve private receipts and checkout statements. No online charge or bank transfer is initiated.

See Swagger UI for every route and schema, or download the generated tool contract. The adapter has no direct database access or arbitrary HTTP tool.

Making a change safely

Read the current resource first. Use its returned _meta.etag as ifMatch. Supply a distinct, stable idempotencyKey for each intended mutation and the typed body. Path parameters stay at the top level. On a timeout or WRITE_OUTCOME_UNKNOWN, retry the same tool, key, payload and precondition; the adapter never automatically retries a write. A definite conflict requires a fresh read and a new decision.

Deletes follow the domain: reservations cancel, units retire, promotions deactivate, notes and feedback redact, drafts archive, and payments reverse. Immutable financial history is retained. Document downloads return an authenticated PDF resource capped at 4 MiB. JSON results are capped at 128 KiB; pages are never followed automatically.

Token or token file

Either AROHA_API_TOKEN or AROHA_API_TOKEN_FILE is sufficient. If both are set, the private token file takes precedence. The examples use a file to keep the secret out of configuration text. Never expires is available on Connect; revocation, current roles, ownership, client ceilings and business rules still apply.

Telemetry and protocol

Every tool call records a real SDK trace, count, duration and completion log. Configure your own approved OTLP destination to export signals; no Aroha/Dynatrace secret is bundled. See telemetry setup. Stdout is reserved for JSON-RPC; completion logs use stderr. This release uses stdio. Remote HTTP/OAuth is deferred.
