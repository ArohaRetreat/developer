API reference · v1

A versioned, scoped API.

Resource routes for the current booking domain. Every mutation passes through the same policy and transaction layer as the website.

Download OpenAPI 3.1
Source contract, not a deployment claim.

This reference lists implemented source routes. The broader 96-operation strategy includes future CMS/access facade, payment, erasure and feedback features that are not exposed here.

Authentication and errors

Send the scoped token in the Authorization header. Errors return a bounded code and request ID. 401 means missing/invalid credentials; 403 means insufficient scope or current permission; 404 also protects another user's resource. 409 indicates a business conflict, 412 a stale version, 428 a missing precondition and 429 a rate limit.

CRUD follows the resource lifecycle

Cancel reservations, reverse recorded payments when that feature ships, retire inventory and revoke grants. There is no raw database-delete API for booking history, issued documents or audit. New room creation/retirement, contact/note editing, external CMS/access management and financial/feedback features remain planned shared-domain work.
